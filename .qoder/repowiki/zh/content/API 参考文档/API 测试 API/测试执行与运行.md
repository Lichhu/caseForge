## 简介
本文件为"测试执行与运行"模块的详细 API 文档，覆盖以下能力：
- 单用例和多步骤用例执行与执行集批量执行
- 执行参数配置（并发度、编码、环境服务选择）
- 超时控制与错误处理
- 结果收集、状态追踪与报告导出
- 并发调度、性能优化与资源管理建议
- 故障恢复与重试策略建议
- **新增**：多步骤用例执行、并行执行组、步骤级调试功能

该模块基于 NestJS 构建，采用 TypeORM 持久化执行记录与结果，并通过控制器暴露 REST 接口。

## 项目结构
围绕"测试执行与运行"的关键文件组织如下：
- 控制器层：对外暴露执行、查询、报告导出等接口
- 服务层：封装执行逻辑、并发调度、断言与环境变量替换

- DTO 层：输入参数校验与 API 规范
- 共享类型：统一的运行状态、请求/期望模型、步骤定义

## 架构总览
系统采用分层设计：控制器负责路由与参数校验，服务层承载业务流程，实体层负责数据持久化。执行流程从控制器进入，经由执行服务完成并发调度与断言，最终写入运行与项表；执行集服务用于管理执行集及其用例集合。

```mermaid
sequenceDiagram
participant Client as "客户端"
participant Ctrl as "ApiTestController"
participant ExecSvc as "ApiExecutionService"
participant EnvSvc as "ApiEnvironmentService"
participant DB as "数据库"
Client->>Ctrl : POST /api-test/{projectId}/transactions/{transactionId}/runs
Ctrl->>ExecSvc : runCases({caseIds, environmentId, ...})
ExecSvc->>EnvSvc : getRuntimeEnvironment(...)
EnvSvc-->>ExecSvc : RuntimeEnvironment
ExecSvc->>DB : 创建 ApiTestRun 记录
loop 并发执行
ExecSvc->>ExecSvc : executeSingleCase(...)
alt 多步骤用例
ExecSvc->>ExecSvc : groupParallelSteps()
ExecSvc->>ExecSvc : executeSingleStep() (并行组内)
else 单步骤用例
ExecSvc->>ExecSvc : executeHttpCase()/executeTcpCase()
end
ExecSvc->>DB : 写入 ApiTestRunItem
end
ExecSvc->>DB : 更新 ApiTestRun 状态/计数
ExecSvc-->>Ctrl : 返回执行详情
Ctrl-->>Client : 执行结果
```

## 详细组件分析

### 接口定义与参数说明
- 批量执行（执行集）
  - 方法与路径：POST /api-test/{projectId}/transactions/{transactionId}/execution-sets/{setId}/runs
  - 请求体字段：environmentId（必填）、environmentServiceId（可选）、concurrency（可选，默认值见服务端）、encoding（可选）
  - 响应：返回本次执行详情（包含运行与项）
- 单用例执行
  - 方法与路径：POST /api-test/{projectId}/transactions/{transactionId}/runs
  - 请求体字段：caseIds（必填，数组）、environmentId（必填）、environmentServiceId（可选）、concurrency（可选）
  - 响应：返回本次执行详情
- 步骤调试执行
  - 方法与路径：POST /api-test/{projectId}/transactions/{transactionId}/cases/debug-run
  - 请求体字段：request（必填）、expected（可选）、target（可选）、environmentId（可选）、stepId（可选）
  - 响应：返回调试执行结果（不保存执行记录）
- 查询执行记录
  - 列表：GET /api-test/{projectId}/runs
  - 详情：GET /api-test/{projectId}/runs/{runId}

### 多步骤用例执行与并行组
- **新增**：多步骤用例支持
  - 用例可包含多个步骤（steps），每个步骤有独立的请求、断言和导出配置
  - 步骤支持独立的目标地址和环境配置
  - 步骤间支持变量共享和提取
- **新增**：并行执行组
  - 通过 `parallelWithPrevious` 标记实现步骤级别的并行执行
  - 相邻标记的步骤归入同一并行组，同时发出请求
  - 并行组内步骤互不可见，组完成后合并变量提取结果
- **新增**：步骤级执行上下文
  - 每个步骤有独立的执行上下文，包含用例名称、编号等信息
  - 支持步骤级别的变量替换和数据函数解析

### 并发控制与调度
- 并发调度算法
  - 使用固定大小的并发池，循环分配待执行用例，等待所有并发任务完成
- 并发度范围
  - 最小 1，最大 10；默认 5

  - 每个用例独立执行，结果写入数据库后汇总运行统计
- **新增**：步骤级并发控制
  - 并行组内步骤同时执行，组间顺序执行
  - 支持混合执行模式：并行组与顺序步骤结合

## 性能考量
- 并发度调优
  - 根据目标服务吞吐与网络带宽调整 concurrency；避免超过服务端限流

  - 并行执行组减少整体执行时间

  - 调试记录限制数量避免数据库膨胀

## 故障排查指南
- 常见错误与定位
  - 未找到可执行的启用案例：检查用例 ID 是否存在且启用
  - 执行集为空：确认执行集中是否已添加用例
  - HTTP Base URL 配置错误：需以 http(s):// 开头，否则抛出异常
  - TCP 服务缺少 host/port：需在服务或 Base URL 中提供
  - 请求失败：执行项 responseSnapshot 中包含错误信息
- **新增**：步骤级故障排查
  - 步骤地址配置错误：检查步骤 target.address 配置
  - 并行执行组冲突：检查 parallelWithPrevious 标记是否正确
  - 步骤调试失败：查看步骤调试记录中的错误信息
- 建议排查步骤
  - 校验环境与服务配置
  - 查看执行详情中的请求/响应快照与断言结果
  - 检查并发度与超时设置是否合理
  - 关注数据库中运行与项的状态变化
