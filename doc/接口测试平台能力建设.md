# 接口测试平台能力建设

## 1. 当前能力

### 1.1 已实现

| 能力 | 当前状态 | 说明 |
| --- | --- | --- |
| 项目与交易管理 | 已实现 | 按项目、交易维护接口测试资产 |
| 接口文档维护 | 已实现 | 支持上传、编辑、保存和结构化接口文档 |
| AI 案例生成 | 已实现 | 支持按场景生成案例、查看生成状态和历史、失败重试 |
| 案例维护 | 已实现 | 支持新增、编辑、删除、启停和分页筛选 |
| 单案例调试 | 已实现 | 可选择环境执行单个案例并保存最近调试结果 |
| 环境与服务配置 | 已实现 | 支持环境变量、密钥、HTTP/TCP 服务及服务排序 |
| 请求变量替换 | 已实现 | 执行前可将环境变量和密钥替换到请求内容中 |
| 自动断言 | 已实现 | 支持状态码、响应头、JSONPath、JMESPath、XPath 等断言 |
| AI 断言生成 | 已实现 | 支持批量生成断言、查询状态、查看结果和取消任务 |
| 批量执行 | 已实现 | 支持选择多个案例并按指定并发数执行 |
| 运行记录 | 已实现 | 保存请求快照、响应快照、断言结果、耗时和状态 |
| 测试报告 | 已实现 | 支持汇总统计及 Excel、PDF、HTML 导出 |
| 执行集 | 部分实现 | 支持案例分组、排序、批量运行和保存最近执行结果；尚不具备流程关联能力 |
| SMP 交易同步 | 部分实现 | 支持同步交易及刷新结构化文档 |

### 1.2 尚未实现

| 能力 | 当前缺口 |
| --- | --- |
| 动态函数造数 | 仅支持环境变量和密钥替换，不能在每次执行时动态生成新值 |
| 关联场景案例 | 没有独立的流程或场景模型 |
| 步骤顺序执行 | 执行集运行时按并发任务执行，不保证业务步骤串行 |
| 响应变量提取 | 不能从上一步响应头、JSON 或 XML 中提取值 |
| 步骤间变量传递 | 后续步骤不能引用前一步产生的流水号、Token 或主键 |
| 条件分支 | 不能根据响应结果选择成功、失败或补偿路径 |
| 轮询等待 | 不能循环查询异步任务直到完成或超时 |
| 流程级断言 | 不能验证多个步骤之间的数据变化和状态关系 |
| 清理与补偿 | 没有固定清理步骤，也没有失败后的冲正、撤销机制 |
| 失败处理策略 | 不支持步骤失败后停止、继续、重试、跳转或补偿 |
| 场景级运行诊断 | 没有变量来源、步骤轨迹、分支路径和清理结果展示 |
| 敏感变量脱敏 | Token、密码及提取出的敏感数据可能进入运行快照和报告 |

## 2. 尚未实现能力的实现方案

### 2.1 动态函数造数

#### 实现内容

- 提供 UUID、时间戳、格式化时间和随机数字等内置函数。
- 建立项目级自定义函数库，函数由内置函数、参数和固定文本组合。
- 案例报文字段可以直接选择函数，并将原值作为函数参数。
- AI 根据自然语言生成函数模板，保存前展示试运行结果。
- 单案例调试、AI 断言执行、批量执行和场景执行共用同一个解析入口。

#### 实现方式

1. 新增项目级函数定义表，保存函数名称、参数、模板和说明。
2. 在后端增加统一的模板解析函数，在请求变量替换之后、请求发送之前执行。
3. 在案例报文编辑器的字段操作中增加“绑定动态函数”。
4. 自定义函数只解析模板，不执行任意 JavaScript，限制嵌套层数并禁止循环引用。
5. 运行记录保存最终请求值，同时保留其生成规则用于追溯。

#### 验收结果

同一个案例连续执行两次时，业务流水号等动态字段能够按规则产生不同且有效的值。

### 2.2 关联场景案例

#### 实现内容

新增独立的“场景案例”，用于组合现有单接口案例：

```text
场景案例
  - 场景基本信息
  - 场景变量
  - 前置步骤
  - 业务步骤
  - 校验步骤
  - 清理 / 补偿步骤
```

#### 实现方式

1. 新增场景表和场景步骤表。
2. 每个步骤引用一个现有单接口案例，不复制案例请求和断言。
3. 步骤保存顺序、输入覆盖、提取规则、执行条件和失败策略。
4. 第一版使用列表式步骤编辑，不建设拖拽式工作流设计器。

#### 验收结果

用户能够选择多个已有案例，组成一个可保存、可复制、可执行的业务场景。

### 2.3 步骤顺序执行

#### 实现内容

- 场景步骤默认严格串行执行。
- 前一步完成后，下一步才允许开始。
- 普通执行集继续承担无依赖案例的并发回归，不改造成流程引擎。

#### 实现方式

1. 新增场景执行服务，按步骤排序逐个调用现有单案例执行能力。
2. 每一步生成独立运行明细，并归属于同一次场景运行。
3. 第一步失败时，按配置停止或进入清理、补偿步骤。

#### 验收结果

“新增 -> 查询 -> 修改 -> 再查询 -> 删除”能够严格按配置顺序执行。

### 2.4 响应变量提取

#### 实现内容

- 从响应头提取 Token、Session 等值。
- 从 JSON 响应使用 JSONPath 或 JMESPath 提取值。
- 从 XML 响应使用 XPath 提取值。
- 支持必填提取；提取失败时直接标记步骤失败。

#### 实现方式

1. 复用现有断言中的 JSONPath、JMESPath 和 XPath 解析能力。
2. 步骤配置变量名、来源、表达式、是否敏感和是否必填。
3. 步骤执行完成后立即提取，并写入当前场景运行上下文。

#### 验收结果

创建接口返回的 `customerId`、`orderId` 或响应头 Token 能被后续步骤直接使用。

### 2.5 步骤间变量传递

#### 实现内容

统一支持以下变量作用域：

- 环境变量：环境地址、公共参数等。
- 项目变量：项目内共享的固定配置。
- 场景变量：本次场景运行期间共享。
- 步骤变量：某一步响应提取的结果。

#### 实现方式

1. 扩展现有请求变量替换能力，使其接收场景运行上下文。
2. 采用明确的引用方式，例如 `{{steps.create.orderId}}`、`{{scenario.customerId}}`。
3. 变量不存在时不发送请求，直接报告变量名称和来源步骤。

#### 验收结果

后续步骤不需要人工复制数据，即可使用前序步骤产生的流水号、Token 和业务主键。

### 2.6 条件分支

#### 实现内容

- 根据步骤状态、状态码、响应字段或断言结果决定是否执行下一步。
- 支持成功路径、失败路径和补偿路径。

#### 实现方式

1. 步骤增加简单条件配置：变量或表达式、比较符、目标值。
2. 条件只决定步骤是否执行，第一版不引入任意脚本。
3. 未命中的步骤记录为“已跳过”，并保存判断依据。

#### 验收结果

同一场景可以在受理成功时进入查询流程，在受理失败时进入失败校验或补偿流程。

### 2.7 轮询等待

#### 实现内容

- 支持按固定间隔重复执行查询步骤。
- 配置成功条件、失败条件、轮询间隔和总超时时间。
- 到达成功或失败条件立即停止轮询。

#### 实现方式

1. 将轮询作为场景步骤的一种执行模式，仍复用普通案例执行能力。
2. 限制最大次数和总超时时间，防止无限运行。
3. 保存每次轮询的关键结果，报告默认只展开最后一次。

#### 验收结果

异步任务发起后，平台能够自动查询到最终成功、失败或超时，不需要人工反复点击。

### 2.8 流程级断言

#### 实现内容

- 比较不同步骤提取出的值。
- 验证状态流转、前后余额变化、数据一致性和最终业务结果。
- 支持场景结束后统一判断整体是否通过。

#### 实现方式

1. 复用现有断言比较操作符，断言输入改为场景变量表达式。
2. 场景断言在相关步骤完成后或场景结束时执行。
3. 报告同时展示期望值、实际值和变量来源。

#### 验收结果

能够验证“修改前值 != 修改后值”“冲正后余额 = 交易前余额”等跨步骤关系。

### 2.9 清理与补偿

#### 实现内容

- 清理步骤无论主流程成功或失败都执行。
- 补偿步骤只在指定失败条件下执行。
- 支持删除测试数据、撤销、退款和冲正。

#### 实现方式

1. 为步骤增加普通、清理、补偿三种类型。
2. 主流程结束后统一执行清理步骤，类似 `finally`。
3. 清理失败不能覆盖主流程失败原因，但必须单独记录和告警。

#### 验收结果

场景执行结束后测试数据被清理；主交易失败时可按配置执行撤销或冲正。

### 2.10 失败处理策略

#### 实现内容

每个步骤支持：

- 失败即停止。
- 失败后继续。
- 有限次数重试。
- 进入补偿步骤。

“跳转到任意步骤”和“从失败点续跑”放到后续版本。

#### 实现方式

步骤保存失败策略、重试次数和重试间隔；执行器根据策略控制后续步骤，并始终保证清理步骤可以运行。

#### 验收结果

用户能够清楚配置失败后的行为，运行结果与配置一致，不出现隐式跳过或无限重试。

### 2.11 场景级运行诊断

#### 实现内容

- 展示场景总状态和每一步状态、耗时、请求及响应。
- 展示变量由哪个步骤、哪个表达式产生。
- 展示条件判断、跳过原因、轮询次数和清理结果。

#### 实现方式

1. 新增场景运行和步骤运行记录。
2. 运行时记录步骤序号、输入变量快照、输出变量、判断轨迹和错误信息。
3. 前端使用时间线展示，无需第一版制作复杂流程图。

#### 验收结果

流程失败后，用户能够直接定位失败步骤、缺失变量或未命中的条件。

### 2.12 敏感变量脱敏

#### 实现内容

- 环境密钥和提取变量可以标记为敏感。
- 敏感值不在前端、日志、运行快照和导出报告中明文显示。
- 请求发送时仍能使用真实值。

#### 实现方式

1. 场景运行上下文保存变量值及敏感标记。
2. 写入数据库、日志和报告前统一调用脱敏函数。
3. 默认将密码、Token、Authorization、Cookie 等字段标记为敏感。

#### 验收结果

完整运行链路中可以正常使用 Token 和密码，但所有可查看、可导出的内容均为脱敏值。

## 3. 关联案例需要覆盖的场景

### 3.1 数据闭环

- 新增 -> 查询 -> 修改 -> 再查询 -> 删除 -> 验证不存在。
- 创建客户、账户或订单后，将返回主键传给后续接口。
- 流程结束后自动清理本次生成的测试数据。

### 3.2 幂等与防重

- 使用相同业务流水号重复请求。
- 首次成功后再次提交，验证不重复扣款、不重复建单。
- 并发提交相同请求，验证只有一次业务生效。
- 超时后重试，验证服务端能正确识别原交易。

### 3.3 生命周期与状态流转

- 开始 -> 处理中 -> 成功或失败。
- 申请 -> 审核 -> 授权 -> 生效。
- 下单 -> 支付 -> 发货 -> 完成。
- 正常完成后撤销、退款、冲正或关闭。

### 3.4 认证与前置资源

- 登录获取 Token，后续步骤复用。
- 开户或创建测试用户后执行目标交易。
- 获取验证码、会话、签名或临时凭证后继续调用。
- 不同角色分别完成申请、复核和授权。

### 3.5 异步任务

- 发起任务后轮询查询状态，直到成功、失败或超时。
- 消息发送后查询消费结果。
- 批处理启动后等待批次结束，再验证处理明细。
- 超时后重试查询，但不重复发起业务操作。

### 3.6 异常、补偿与恢复

- 中间步骤失败后验证未产生脏数据。
- 成功交易执行撤销、退款或冲正，验证余额和状态恢复。
- 模拟下游失败后验证本地回滚或补偿任务。
- 流程中断后从指定步骤续跑。

### 3.7 跨渠道与跨系统

- 手机银行发起，柜面或后台查询结果。
- 渠道 -> 网关 -> 核心 -> 账务或清算系统的链路验证。
- 同一业务在不同渠道提交，验证状态和数据一致性。
- 上游返回成功后，验证下游数据库、对象存储或消息结果。

### 3.8 并发与竞争

- 多请求同时操作同一账户、订单、库存或额度。
- 一个步骤等待时，另一个步骤修改目标数据。
- 验证锁、版本号、余额和限额控制。
- 验证并发场景下的防重与最终一致性。
