# 案例 SQL 步骤

## 是什么

步骤列表里多一种步骤：**SQL 步骤**。选一个数据库连接、写一段 SQL、执行；查出来的结果可以提取成变量，给同一个案例后面的步骤用。

## 用在哪

- **前置改数据**：先 update 打开一个开关或造数，再跑请求步骤。
- **中间取数**：select 查出值，后面的请求步骤用 `${变量名}` 引用。
- **后置核对**（第二步再做）：请求跑完 select 核对落库数据对不对。

## 怎么配

案例的步骤列表里现在有两种类型，按顺序排在一条列表里：请求步骤（现有能力不变）、SQL 步骤。

SQL 步骤的配置项：

- 数据库连接：手动选，复用现有「数据库连接」里维护的那套。
- SQL 语句。
- 结果提取：变量名 + 字段名，可以标"必填"。
- 影响行数上限、超时：有默认值，一般不用改。

## SQL 规则

- 查（select）和改（update）都支持。
- **update 必须带 where**，不带不允许保存。
- **update 影响 0 行就报错停下**，大概率是条件写错了，不能当成功继续跑。
- 影响行数超过上限、或执行超过超时时间，报错停下。
- 只读的连接不允许执行 update。
- SQL 里取值直接写 `${变量名}`（共享变量）或 `${函数名(参数)}`（数据函数），执行前替换成真实值。
  编辑器提供「插入变量 / 插入函数」从列表里选，不用手打。替换时值里的单引号按 SQL 字面量转义（`'` → `''`），
  避免值里带引号把语句写坏。不做驱动参数绑定，所以别把变量放在需要严格类型的位置（如数字比较建议整体加引号或确保取值干净）。
- 变量取第一行；标了必填但取不到值，直接报错停下，避免后面的请求带着空值跑出去。

## 执行顺序与排队

- SQL 步骤默认串行执行。
- **排队规则**：案例里只要有 SQL 步骤就参与排队，资源名默认等于数据库连接。
- 同一个资源名，同一时间只允许一个案例在跑，其他案例排队等。
- 位子从 SQL 步骤开始，一直占到**整个案例跑完**才释放。不是 SQL 执行完就放 —— 否则你改完开关，别人接着改掉，你后面的请求就错了。
- 查和改都参与排队：只是 select 的案例也会被别人改动的数据影响。
- 纯请求的案例不受影响，照旧并发跑。

### 位子什么时候释放

- 案例一结束就放：跑完、报错、超时都放。失败路径上也必须释放，不能因为一个案例出错就把整个库锁死。
- 锁带最长持有时间（默认 10 分钟），到点自动释放。万一服务崩了或哪条路径漏了释放，也不会永久卡住。
- 排队也有等待上限（默认 5 分钟），等太久就报「前方案例正在占用该库，请稍后重试」，不让人无限干等。
- 这套锁存在进程内存里，服务重启即清空，不存在锁死无法恢复的情况。
- 代价：多实例部署时锁不通用。当前是单实例，先这样，以后多实例再换共享存储的锁。

## 失败与数据还原

- SQL 步骤失败 → 案例停下，后面的步骤不跑。
- 改过的数据不会自动还原。需要还原就在案例最后再加一个 SQL 步骤改回去。
- 第一版不做事务回滚：这个场景就是想让接口真的看到改动，把改动放在未提交的事务里接口读不到，回滚行不通。

## 界面

- 步骤列表加类型标识；「环境 / 地址」列对 SQL 步骤显示连接名。
- 新增步骤时先选类型：请求 / SQL。
- SQL 步骤表单：连接下拉 + SQL 输入框（带「插入变量 / 插入函数」）+ 影响行数上限 + 超时 + 变量提取表。
- 执行结果和报告里显示 SQL、返回行数 / 数据、耗时。

## 复用已有能力

数据库连接池、12 种库型适配、密码加密、表结构元数据都已经在「数据函数」里实现了，SQL 步骤直接复用，不重写。数据函数本身保持只读，行为不变。

## 分两步做

**第一步（本次）**：SQL 步骤 + select 提取变量 + update 带护栏 + 排队。

**第二步（以后）**：SQL 步骤上做断言（查库核对落库结果）、清理步骤无论成败都执行、排队状态在界面上可见。

### 第一步实现状态

已实现：

- 步骤类型：`ApiCaseStep` 为请求步骤 / SQL 步骤的判别联合，`kind` 缺省按请求步骤处理，历史数据不用迁移（`steps` 是 json 列）。
- SQL 步骤配置：数据库连接、SQL、影响行数上限、超时；取值直接在 SQL 里写 `${变量名}` 或数据函数。
- 执行：`SqlStepRunnerService` 负责校验、只读拦截、行数护栏、超时；变量替换在 `substituteSqlVariables`（带 SQL 字面量转义），驱动适配与数据函数共用 `database-pool.util`。
- 排队：`db-step-lock.util` 按资源名（默认数据库连接）占位，案例跑到第一个 SQL 步骤时占位，案例结束（跑完 / 报错 / 超时）释放，带 10 分钟持有上限与 5 分钟排队上限。
- 变量提取：`row`（首行字段）、`rows`、`rowCount`、`affectedRows`。
- 界面：新增步骤可选类型，步骤列表带 SQL 标记并显示连接与 SQL 摘要，SQL 步骤显示「串行」，SQL 面板含连接、SQL、护栏与「插入变量 / 插入函数」（按光标插入），变量提出来源按类型切换。
- 试运行：SQL 面板的「试运行」按钮，查询语句直接执行并返回字段名与最多 50 行样例；弹窗里每个字段都能一键「提取」成变量，不用猜字段名。改数据语句在事务里执行后强制回滚，只报告影响行数，数据不落库。
- 报告：SQL 步骤展示连接、模式、SQL 与执行结果。

第一版的边界：

- **只支持 select / update**：insert、delete、DDL 会被拦掉；数据库连接新建时默认「只读」，要执行 update 需先在连接上取消只读。
- **影响行数上限是执行后校验**：能立刻发现问题并让案例失败，但无法阻止已经发生的改动；误改需要另加一个 SQL 步骤改回去。
- **SQL 步骤单步调试留到第二步**：案例整体执行已支持，编辑器里的「调试」按钮对 SQL 步骤暂时禁用。
- 改数据试运行的代价：回滚依赖数据库事务，MyISAM 这类非事务引擎回滚不了；自增序列、触发器里的外部调用等副作用也不会回滚。达梦驱动没有 rollback 能力时会直接提示不支持，避免误以为已回滚。
- **结果快照最多保留 100 行明细**（`rowCount` 仍记真实行数），`rows` 变量取到的也是快照里的行。
- SQL 步骤不参与并发组，始终串行。

## 已知边界

- 连接写死在步骤里，换库要改步骤（已确认接受）。
- 粘贴步骤到别的项目时连接 ID 可能不存在，给提示。
- AI 生成案例只产请求步骤，保存时要把已有 SQL 步骤原样保留，不能被覆盖。
- SQL 原文会进报告，别在里面写敏感数据。
- 调试前置步骤命中 SQL 步骤时按单步占位（调试是人手动触发，可接受）。

## 验证

- 单测：SQL 步骤执行、where 校验、影响行数校验、必填变量取不到报错、同资源名排队互斥、失败与超时后位子正常释放、排队等待超时。
- 手工：改数据 → 发请求 → 变量引用，跑通全链路。

已加的单测文件：`db-step-sql.util.spec.ts`（语句校验 / 取值替换与转义 / 上下限 / 并发分组）、`db-step-lock.util.spec.ts`（互斥 / 并行 / 等待超时 / 自动释放 / 会话释放）、`sql-step-runner.service.spec.ts`（只读拦截 / 影响行数 / 超时 / 结果），`api-execution.db-step.spec.ts`（执行链路 / 变量替换 / 变量提取 / 失败中断 / 占位时机）。
