# 动态造数函数方案设计

## 1. 背景与目标

### 背景

案例请求报文中的部分字段值是写死的，但被调方要求某些字段每次请求必须唯一（典型如 `msgId`）。
目前只能手工改值，无法支撑调试、批量执行、执行集跑批等场景。

### 目标

- 报文中的任意字段值都可以通过「函数」动态生成，执行时每次产生新值
- 函数可复用（项目级函数库），可带参数（基于原值做变换）
- 从示例报文入手绑定函数，用户不需要学习模板语法
- 函数定义支持 AI 生成：用户描述规则，AI 产出函数
- 所有执行路径（单案例调试、批量 AI 断言、执行集跑批）统一生效

### 非目标（暂不做）

- 关联参数（从上一个响应提取值给下一个请求使用）
- 任意 JS 脚本执行（仅在模板表达不了时按需引入沙箱，见三期）

## 2. 核心概念

### 2.1 内置原语（代码实现，不可修改）

| 原语                | 说明                                | 示例输出                      |
| ------------------- | ----------------------------------- | ----------------------------- |
| `${uuid}`           | 标准 UUID v4                        | `550e8400-e29b-41d4-a716-...` |
| `${timestamp}`      | 毫秒时间戳                          | `1752666000000`               |
| `${timestamp:格式}` | 格式化当前时间，如 `yyyyMMddHHmmss` | `20260716194801`              |
| `${random:N}`       | N 位随机数字                        | `4827`（N=4）                 |

> 后续可按需扩充银行业务原语：`${idcard}`（身份证）、`${bankcard}`（Luhn 卡号）、`${mobile}`（手机号）等。

### 2.2 自定义函数（模板组合，项目级存储）

函数体 = 内置原语 + 参数 + 字面量的拼接模板，**不是可执行代码**。

```
名称：MSG
参数：base
模板：${base}${timestamp:ms}
说明：原值追加毫秒时间戳，保证 msgId 唯一
```

使用（参数在绑定时固化为字面量）：

```json
{ "msgId": "${MSG('QYCX007062')}" }
```

每次执行生成：`QYCX0070621752666000000`

### 2.3 解析顺序

```
报文模板
  → 展开自定义函数（代入参数，限最大 3 层嵌套，禁止循环引用）
  → 解析内置原语
  → 得到最终报文 → 发送
```

## 3. 使用流程（从示例报文入手）

```
案例请求报文编辑器
  → 解析报文为字段树（key: value，支持 JSON / XML 路径）
  → 用户点击某字段（如 msgId: "QYCX007062"）
  → 弹出函数选择器：
      - 从项目函数库选择已有函数
      
      - 新建函数（手工填模板 或 AI 生成）
  → 原值作为参数固化，字段值替换为占位符 ${MSG('QYCX007062')}
  → 保存案例（案例里存的是模板）
```

执行时（调试 / 批量 / 执行集）后端在发送前完成解析，每次都生成新值。

## 4. AI 生成函数

### 流程

```
用户输入规则描述（自然语言）
  例：「msgId 规则是 MSG 前缀 + 17 位时间戳 + 4 位随机数字」
  → AI 产出模板：MSG${timestamp:yyyyMMddHHmmss}${random:4}
  → 系统自动试跑 5 次，展示样例值供用户确认
  → 确认后保存到项目函数库
```

### 要点

- **AI 生成 ≠ AI 执行**：AI 只在定义函数时调用一次；执行时是确定性的本地解析，跑批不依赖 AI
- AI 产出的模板可人工查看、修改、试跑，不是黑盒
- 复用现有 `AiWorkflowService`，新增一个小的 prompt 场景

## 5. 数据模型

新表 `api_custom_function`（项目级）：

| 字段        | 类型        | 说明                                     |
| ----------- | ----------- | ---------------------------------------- |
| id          | uuid        | 主键                                     |
| projectId   | uuid        | 所属项目                                 |
| name        | varchar(64) | 函数名，项目内唯一，不得与内置原语重名   |
| params      | json        | 参数名列表，如 `["base"]`                |
| template    | text        | 模板体，如 `${base}${timestamp:ms}`      |
| description | text        | 规则说明（也是 AI 生成时的输入）         |
| type        | enum        | `template`（一期）/ `script`（三期预留） |
| 审计字段    |             | createdBy / updatedAt 等，与现有表一致   |

维护入口见第 6 节「函数平台」。

## 6. 函数平台（函数库管理）

### 6.1 入口位置

参照现有环境维护（`ApiEnvironmentMaintainModal.vue`）模式，两个入口：

- **全局入口**：接口测试模块顶部「更多」菜单加「函数库」，打开管理弹窗（项目级，管理所有函数）
- **就地入口**：报文字段树点字段绑函数时，函数选择器里带「新建函数」按钮——用户在用的时候顺手创建，不用跳转

### 6.2 管理页布局（左列表 + 右编辑器）

```
┌─────────────────────────────────────────────┐
│ 函数库（项目级）                  [+ 新建]   │
├───────────────┬─────────────────────────────┤
│ 函数列表       │ 名称:  MSG                  │
│ ● MSG         │ 参数:  base                 │
│ ● ORDER_NO    │ 模板:  ${base}${timestamp:  │
│ ● TRACE_ID    │        yyyyMMddHHmmss}      │
│               │ 说明:  原值追加时间戳保证唯一 │
│               ├─────────────────────────────┤
│               │ [AI 生成] [试跑]             │
│               │ 试跑样例（5 次）:            │
│               │  QYCX00706220260716201501   │
│               │  QYCX00706220260716201502   │
│               │  ...                        │
│               │          [删除]  [保存]      │
└───────────────┴─────────────────────────────┘
```

### 6.3 核心功能点

- **列表**：名称、参数、说明、被引用次数（哪些案例在用——删除前提示）
- **编辑器**：名称 + 参数声明 + 模板 + 说明；保存时校验（重名、未知原语、循环引用）
- **试跑预览**：前端用 shared 解析引擎本地跑 5 次展示样例值——防错的关键环节
- **AI 生成**（二期）：编辑器里一个输入框「描述生成规则」，AI 填充模板字段，用户试跑确认后保存
- **内置原语说明**：管理页附一个只读的原语清单（uuid/timestamp/random 用法），当文档用

### 6.4 作用域层级

- **项目级（一期默认）**：每个项目一套函数库，隔离干净。银行场景里不同系统的规则往往不同，避免「改一个函数影响所有项目」的风险
- **跨项目复用**：不做全局共享，如有需要提供「从其他项目复制」功能，比全局共享安全

## 7. 解析器规则

- 语法统一使用 `${...}`：
  - `${name}` / `${name:arg}` → 先查自定义函数表，未命中按内置原语处理
  - `${name('literal', ...)}` → 带参调用自定义函数
- 展开限制：最大嵌套 3 层；检测循环引用（A→B→A）直接报错
- 未定义函数：解析时明确报错（避免把 `${MSG}` 字面量发给被调方而不自知），错误信息包含函数名与所在字段路径
- 参数转义：字面量参数中的引号需转义，解析器负责还原
- 类型处理：一期仅支持字符串字段；若整个值恰为一个占位符且结果为纯数字，可选还原为数字（二期再定）
- XML / Text 报文：按字符串统一替换，不限于 JSON

实现位置：

- 解析引擎放 `packages/shared`（如 `dynamic-value.util.ts`），前后端共用
  - 前端用于「试跑预览」
  - 后端用于执行前的真实解析
- 后端注入点：`ApiExecutionService` 发送请求前，对 body / headers / query / path 统一解析

## 8. 分期计划

| 期   | 范围                                                                                          | 交付物                                |
| ---- | --------------------------------------------------------------------------------------------- | ------------------------------------- |
| 一期 | 解析引擎 + 内置原语 + 带参模板函数 + 函数平台（CRUD + 试跑）+ 报文字段树绑定入口 + 执行时解析 | 手工定义函数即可用，msgId 场景闭环    |
| 二期 | 函数平台内嵌 AI 生成（描述 → 模板 → 试跑预览 → 保存）；按需补充业务原语                       | 用户零门槛造函数                      |
| 三期 | 函数编辑器支持受限脚本沙箱（仅当模板表达不了的算法类规则，如校验位）                          | `type: script`，沙箱禁 IO、限时限内存 |

## 9. 风险与对策

| 风险                                      | 对策                                                    |
| ----------------------------------------- | ------------------------------------------------------- |
| 断言联动：响应回显 msgId 时写死断言会失败 | 一期不处理；AI 生成断言时可跳过此类动态字段（后续优化） |
| 循环 / 深层嵌套引用                       | 解析器限深度 3 层 + 循环检测报错                        |
| 命名冲突                                  | 自定义函数禁止与内置原语重名（保存时校验）              |
| AI 理解错规则                             | 保存前强制试跑展示样例值，由用户确认                    |
| 脚本安全（三期）                          | 沙箱（quickjs / node:vm）+ 禁 IO + 50ms 超时 + 内存限制 |

## 10. 端到端示例

```
1. 用户在函数库新建（或 AI 生成）：
   MSG(base) = ${base}${timestamp:yyyyMMddHHmmss}${random:4}

2. 在案例报文字段树点击 msgId，绑定 MSG：
   { "msgId": "${MSG('QYCX007062')}" }

3. 调试执行，后端解析后实际发送：
   { "msgId": "QYCX007062202607161948014827" }

4. 再次执行，生成新值：
   { "msgId": "QYCX007062202607161948123391" }
```
